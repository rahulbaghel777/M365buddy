Email PowerShell Reports Using Microsoft Graph

Replace SMTP delivery with Microsoft Graph when the report must be emailed but an SMTP relay is not available.

Where this fits: This is the email-delivery option for the SharePoint Site Inventory script.

When should you use Microsoft Graph instead of SMTP?

Use this option when the Site Inventory script must continue to email the CSV but your organization does not provide an SMTP relay that the script is allowed to use.

What replaces the SMTP section?

Do not put an Exchange Online hostname into $SmtpServer. Instead, replace the old Send-MailMessage delivery block with a Microsoft Graph mail-sending block that authenticates using an approved Entra ID application.

Keep these parts unchanged: site collection discovery, report building, Export-Csv, storage calculations and output path. The change is only the email-delivery portion.

What do I put where?

Old SMTP settingGraph-based replacement
$SmtpServerRemove it. Graph sends through Exchange Online; you do not provide an SMTP server.
$FromUse the approved mailbox/user that is permitted to send the report.
$ToKeep the recipient addresses here or in the Graph request body.
SMTP authenticationReplace with the approved Entra ID app/certificate authentication described in the Entra setup article.

Entra ID application requirements

Use an Entra ID application that is approved for unattended reporting. Grant the Microsoft Graph mail permission required by your organization's design (commonly Mail.Send for application-based sending), then obtain admin consent.

If you are using the same certificate-authenticated application pattern as the Site Inventory script, keep the certificate and private key secure and use the same tenant/client/certificate values where appropriate.

Related setup: Register an Entra ID App for PnP PowerShell Certificate Authentication

Example delivery pattern

# Keep your existing report generation above this point.

# 1. Create the CSV with Export-Csv
# 2. Acquire an Entra ID access token for Microsoft Graph
# 3. Build a /users/{sender}/sendMail request
# 4. Attach the generated CSV as an email attachment
# 5. Send the request to Microsoft Graph

# Do not hard-code secrets or certificate passwords.

The exact Graph authentication and sendMail implementation should match your organization's approved authentication model. The important change is that the SMTP variables and Send-MailMessage call are no longer used.

Save the script and run it normally

After replacing the SMTP/email portion with the approved Graph implementation, save the .ps1 file. Then follow the same execution process from the Site Inventory article:

Get-ExecutionPolicy -List

# If allowed for your user:
Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned

cd "C:\Scripts\SharePoint"
.\SharePoint_Site_Inventory.ps1
Preferred: Open PowerShell 7 as Administrator during setup and troubleshooting. If execution policy is controlled by Group Policy or Intune, do not bypass it.

Test before scheduling

  1. Run the script manually.
  2. Confirm the CSV is created.
  3. Confirm the email is delivered.
  4. Check the sender mailbox and recipient mailbox.
  5. Only then move the script into Task Scheduler, Azure Automation or another approved unattended process.

Security

  • Never put a PFX password, private key or client secret in public code.
  • Use the minimum approved Graph permissions.
  • Use a dedicated reporting mailbox where appropriate.
  • Do not expose access tokens in transcript files or logs.
