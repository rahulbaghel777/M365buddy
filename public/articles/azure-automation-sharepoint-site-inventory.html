Automate SharePoint Online Site Inventory with Azure Automation

By Rahul Baghel, creator of M365Buddy

Automate recurring inventory reports for SharePoint Online using Azure Automation, a compatible PowerShell runtime, PnP.PowerShell, certificate-based app authentication, and Microsoft Graph email delivery.

Azure AutomationPowerShell 7.4PnP.PowerShellEntra IDMicrosoft Graph

This guide explains how to configure and use the accompanying Azure Automation SharePoint Online Site Consumption Report runbook. Follow the setup steps, configure the required Automation variables and app permissions, then use the built-in script viewer/editor below to review, customize, copy, or download the PowerShell file without leaving this page.

What the script does

1Load settingsAutomation variables
2ConnectPnP certificate auth
3Build reportSites, owners, storage
4DeliverCSV or ZIP by Graph

When the runbook starts, it reads eight required Azure Automation variables, imports PnP.PowerShell, connects to the SharePoint admin center using certificate-based app authentication, and retrieves the tenant's site inventory. It loads Microsoft 365 group visibility into a cache, then processes sites one by one. A site failure is logged as a warning and recorded for the final console summary so the loop can continue.

After processing, the script exports successful records to a timestamped CSV in the runbook's temporary directory. It then sends the report as an email attachment using Microsoft Graph. If the CSV is 3 MB or larger, it attempts to compress it into a ZIP first; if that ZIP is still 3 MB or larger, the current Mail.Send-only approach throws an error rather than sending it.

1. Prerequisites and permissions

  • An Azure subscription and permission to create or manage an Azure Automation Account and runbooks.
  • A PowerShell runtime environment with a compatible version of PnP.PowerShell available to the runbook.
  • An Entra ID application and certificate suitable for app-only SharePoint authentication.
  • SharePoint application permission Sites.FullControl.All, as documented in the script, with admin consent where required. Review whether this broad permission is acceptable for your governance model.
  • A Microsoft Graph application registration for the email/group lookup logic, with Group.Read.All and Mail.Send application permissions and admin consent.
  • A valid sender mailbox, the required Exchange/Microsoft 365 authorization for the app to send from it, and the intended recipient list.
Least privilege: The script uses separate variable names for the SharePoint app and Graph mail app. Confirm the app IDs correspond to the intended registrations. Do not grant permissions simply because they appear in this guide; compare them with the actual API calls and your organization's approval process.

2. Create the Automation Account and runtime

In the Azure portal, open Automation Accounts and create or select the account that will host the runbook. Choose the subscription, resource group, and region according to your organization's standards. Then configure a PowerShell runtime environment compatible with the PnP.PowerShell version you intend to use.

Import or make PnP.PowerShell available in that runtime environment, and verify that package import completes before running the script. The runbook checks for several PnP commands after importing the module, which helps expose a missing or incompatible module early. Do not assume that a module installed on your workstation is automatically available in Azure Automation.

3. Configure the SharePoint certificate app

  1. In Microsoft Entra admin center, create or select the app registration used for SharePoint access.
  2. Upload the public certificate to the app registration.
  3. Record the tenant identifier and application (client) ID.
  4. Prepare the matching PFX content and its password for the runbook's protected configuration.
  5. Grant and obtain admin consent for the approved SharePoint application permission.

The script reads PfxBase64 and PFX Password from Automation variables. It converts the password string to a SecureString and uses Connect-PnPOnline with -CertificateBase64Encoded, -CertificatePassword, -Tenant, and -ClientId. The certificate used by the runbook must match the certificate registered on the app.

4. Configure the Microsoft Graph mail app

The current implementation requests a Graph access token using the client-credentials flow and a client secret. The Graph app is used to read Microsoft 365 group visibility and send the report. Configure the required Graph application permissions and admin consent, and verify that the sender mailbox is authorized under your tenant's Exchange application access controls.

Credential design: The current script uses a client secret for Graph. Store it in a protected Automation variable or approved secret store; never place a real secret in the script, article, Git history, or screenshots. Consider whether your organization requires a more restrictive secret-management approach before using this implementation.

5. Create the eight Automation variables

In the Automation Account, open Variables and create each variable using the exact spelling shown below. The script treats all eight as required and stops if any is empty.

The script parses MailTo into individual recipients using commas, semicolons, or newlines. Check that the recipient list is correct before the first run. Where possible, mark secret variables as encrypted and limit who can read or edit Automation Account variables and runbook jobs.

6. Update the tenant-specific configuration

Open the downloaded script in a code editor and locate the configuration section near the top:

$AdminUrl = "https://5062x8energy-admin.sharepoint.com"

Replace the example tenant-specific URL with your SharePoint admin center URL, for example https://yourtenant-admin.sharepoint.com. Do not change it to the regular SharePoint home URL. Save the updated script and upload it to the runbook after reviewing the diff.

The configuration section also defines the CSOM request timeout, retry count and delays, Graph token refresh buffer, and the 3 MB attachment threshold. Those are script settings, not Automation variables, so changing them requires editing the script itself.

7. Understand the report columns

For each site processed successfully, the CSV currently contains these columns:

CSV columnMeaning in this script
SiteNameTitle of the site's web returned by Get-PnPWeb.
SiteUrlURL of the site from the tenant inventory.
SiteCreatedDateCreation date returned by the web object, formatted as yyyy-MM-dd.
LastActivityDateTenant inventory's LastContentModifiedDate, formatted as yyyy-MM-dd.
SPOwnersOwner-group member email addresses, falling back to login name or title where needed.
SiteCollectionAdminsSite users whose IsSiteAdmin property is true, rendered as email/login/title values.
Office365VisibilityMicrosoft 365 group visibility when the site has a resolvable group ID: Public or Private; otherwise blank.
StorageUsedGBSite storage usage from the tenant inventory, converted from MB to GB and rounded to two decimals.

The tenant summary printed in the job output and included in the email body reports storage quota, consumed and available storage, total sites, private group sites, and public group sites. Group visibility is not a general site-sharing setting: non-group-connected sites may have a blank Office365Visibility value.

8. Import and publish the runbook

  1. Download the .ps1 file using the link at the top of this guide.
  2. Replace the tenant-specific $AdminUrl value and make any approved configuration changes.
  3. In Azure Automation, create a PowerShell runbook and paste/import the reviewed script.
  4. Select the intended runtime environment and confirm PnP.PowerShell is available.
  5. Save the runbook, review it, and publish it when it is ready to test.

The script calls Get-AutomationVariable, so it is intended to run inside Azure Automation rather than directly in a normal PowerShell terminal unless you provide an equivalent test harness for those variables.

9. Run a controlled test

Start with a manual test run before creating a schedule. Monitor the job output and warnings. The script reports the discovered site count, periodically prints site progress, retries selected operations, records failures, exports successful results, and attempts email delivery.

  • Confirm the job connects to the SharePoint admin center and discovers the expected number of sites.
  • Verify that the CSV contains the expected columns and that sample site URLs, owners, admin values, visibility, and storage values look reasonable.
  • Confirm that public/private visibility is present only where the associated Microsoft 365 group can be resolved.
  • Check the job output for failed sites; failures are reported in the console/job stream and are not added as status/error columns to the CSV.
  • Confirm the email arrives at the intended recipients and that the attachment opens correctly.
Do not rely on “Completed” alone. Validate report completeness and email delivery independently. A successful job status does not guarantee every site was processed or that the email reached the recipients.

10. Understand email delivery and attachment limits

The runbook creates a timestamped CSV in the temporary directory, then uses Microsoft Graph's /users/{MailFrom}/sendMail endpoint to send the report. If the CSV is at least 3 MB, it compresses the CSV and attempts to attach the ZIP instead. If the ZIP also reaches the configured 3 MB threshold, the script throws an error and asks for an alternate delivery design.

The temporary CSV is not a durable report archive. If you need long-term retention, audit evidence, or a download link, extend the script to store the report in an approved SharePoint library or other governed storage location and apply the appropriate access and retention controls.

11. Schedule recurring runs

After the manual run is validated, create a schedule in Azure Automation and link it to the published runbook. Select a cadence suitable for the number of sites and the reporting need. Verify the schedule time zone and first run. Review job history, warnings, report delivery, and runtime after the first scheduled execution.

Troubleshooting

SymptomChecks to perform
Get-AutomationVariable or empty-variable errorRun inside Azure Automation and confirm all eight variable names match exactly, including the space in PFX Password.
Cannot connect to SharePointCheck $AdminUrl, tenant/client IDs, PFX content/password, certificate registration, module version, and admin consent.
PnP cmdlet not foundCheck the runtime environment and the installed/available PnP.PowerShell package.
Graph token request failsCheck Tenant, MailClientId, MailClientSecret, secret expiry, and Graph application permission consent.
Group visibility is blankThe site may not be group-connected, or its group may not have been resolvable. Check the group ID and Graph permissions.
Owner or admin fields are blankCheck whether the site has an associated owner group and whether the connected identity can read users and group members.
CSV generated but email failsValidate MailFrom, MailTo, Graph send permission, Exchange application restrictions, and the Graph error details in the job output.
Attachment is too largeThe script tries ZIP compression for CSV files at least 3 MB. If the ZIP remains at least 3 MB, use an approved storage-and-link approach or redesign delivery with the required permissions.
Job runs too longThe script comments note the Azure Automation sandbox's hard three-hour runtime limit. Measure the actual job duration for your tenant and consider splitting the inventory into batches or using an execution platform suited to longer workloads.

Security and operational checklist

  • Replace the hard-coded tenant-specific admin URL before use.
  • Keep PFX data, PFX password, and Graph client secret out of source control and protect them in Automation/secret storage.
  • Review the broad SharePoint application permission and Graph application permissions with your security team.
  • Track certificate and client-secret expiry and establish a rotation process.
  • Restrict who can edit runbooks, read variables, and view job output.
  • Test the report with a limited recipient list and verify the output before broad distribution.
  • Plan for runtime, attachment-size, retention, and failed-site handling as the tenant grows.

Conclusion

This runbook combines SharePoint site inventory, owner/admin lookup, group visibility, storage reporting, CSV export, and Microsoft Graph email delivery in one scheduled workflow. The safest path is to configure the required variables carefully, replace the tenant-specific settings, validate permissions, and complete a manual test before enabling a recurring schedule.
