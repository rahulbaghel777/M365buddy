Export All SharePoint Online Sites Using PnP PowerShell

Learn how to generate a SharePoint Online site inventory and storage usage report using PnP PowerShell, Microsoft Entra ID certificate authentication, SharePoint tenant commands, and CSV export.

Important: This article is based on a SharePoint Online reporting script. Before using it in production, review the permissions, certificate configuration, SMTP settings, and security requirements with your Microsoft 365 administrator.

What does this script do?

Managing a large SharePoint Online environment can be difficult when site information is spread across different administration pages. This PowerShell script creates a consolidated report containing SharePoint site information, storage usage, site type, web creation date, site collection administrators, SharePoint owners, and Microsoft 365 Group visibility.

The script performs the following activities:

  1. Connects to the SharePoint Online Admin Center.
  2. Retrieves SharePoint Online site collections.
  3. Excludes redirect sites.
  4. Retrieves tenant storage allocation.
  5. Processes each SharePoint site.
  6. Connects to individual SharePoint sites.
  7. Retrieves the root web creation date.
  8. Retrieves SharePoint site collection administrators.
  9. Retrieves members of the associated SharePoint Owner Group.
  10. Identifies Microsoft 365 Group-connected sites.
  11. Retrieves Microsoft 365 Group visibility as Public or Private.
  12. Classifies the SharePoint site type.
  13. Calculates storage usage in GB.
  14. Exports the final results to CSV.
  15. Validates the CSV columns.
  16. Calculates storage utilization and over-utilization.
  17. Sends an email containing the CSV attachment.
  18. Deletes the temporary CSV after successful email delivery.

Prerequisites

1. PowerShell 7 or later

PowerShell 7 or later is required because the script uses ForEach-Object -Parallel to process multiple sites.

Check your PowerShell version:

$PSVersionTable

Confirm that the PSVersion value is 7 or later.

2. PnP PowerShell

Install the PnP PowerShell module from PowerShell 7: 

Install-Module PnP.PowerShell -Scope CurrentUser

Verify that the module is installed:

Get-Module PnP.PowerShell -ListAvailable

Import the module:

Import-Module PnP.PowerShell

3. Microsoft Entra ID application

The script uses an application registered in Microsoft Entra ID for certificate-based app-only authentication.

You will need:

  • Microsoft Entra ID application registration
  • Application or Client ID
  • Tenant ID or tenant domain
  • Public certificate uploaded to the application
  • Private certificate available on the execution computer
  • PFX certificate password
  • Required SharePoint and Microsoft Graph permissions
  • Admin consent for the required permissions
Related setup article:

Register an Entra ID App for PnP PowerShell Certificate Authentication

This linked article will explain application registration, certificate creation, certificate upload, API permissions, admin consent, and authentication testing.

4. Certificate file

The script requires a PFX certificate file. A PFX file normally contains the certificate and private key protected by a password.

Example certificate path:

C:\Certificates\SharePointAutomationCert.pfx

The certificate path must be updated in the script before execution.

5. SMTP configuration

The script sends the report through an SMTP server. Your organization must provide an approved SMTP relay or email delivery method.

Example configuration:

$From = "SharePointReport@contoso.com"

$To = @(
    "admin@contoso.com"
)

$SmtpServer = "smtp.contoso.com"

Replace these example values with the SMTP details approved for your environment.

6. Output folder

The script creates the output directory if it does not already exist. The account running the script must have permission to write to this folder. 

C:\Reports\SharePointSiteInventory

How to execute the script

Step 1: Save the script

Save the PowerShell file with a name similar to: 

Get-SharePointOnlineSiteInventory.ps1

Step 2: Open PowerShell 7

Open PowerShell 7 and navigate to the folder where the script is saved. 

cd "C:\Scripts\SharePoint"

Step 3: Run the script

.\Get-SharePointOnlineSiteInventory.ps1

The script will display progress information while it retrieves and processes the SharePoint sites.

Optional: Check execution policy

If PowerShell blocks the script, check the current execution policy: 

Get-ExecutionPolicy

If permitted by your organization's security policy, you can temporarily bypass the policy for the current PowerShell session: 

Set-ExecutionPolicy `
    -Scope Process `
    -ExecutionPolicy Bypass

Then run the script again:

.\Get-SharePointOnlineSiteInventory.ps1

What results will be generated?

The script creates a CSV report containing the following nine columns:

Column Description
SiteName SharePoint site title.
SiteUrl SharePoint site URL.
SiteType Classified type of SharePoint site.
Template SharePoint site template.
WebCreatedDate Root web creation date.
Office365Visibility Microsoft 365 Group visibility: Public or Private.
StorageGB Current site storage usage in GB.
SiteCollectionAdmins Site collection administrators.
SPOwners Members of the associated SharePoint Owner Group.

Storage calculation

SharePoint storage usage is reported in MB by the tenant-level command. The script converts MB to GB using the following formula: 

StorageGB = StorageUsageCurrent / 1024

Tenant allocated storage is also converted from MB to GB: 

$TotalAllocatedStorageGB =
    [Math]::Round(
        ($TenantInfo.StorageQuota / 1024),
        2
    )

The script displays TB values only for reporting purposes. The conversion used is: 

1024 GB = 1 TB

Over-utilization calculation

The script calculates over-utilized storage using: 

Over-Utilized Storage =
Used Storage - Allocated Storage

The over-utilized percentage is calculated using: 

Over-Utilized Percentage =
(Over-Utilized Storage / Allocated Storage) * 100

Example:

Allocated storage = 157 TB
Over-utilized storage = 358 TB

358 / 157 * 100 = 228.03%

If the calculated over-utilized storage is negative, the script sets the value to zero.

Email report behavior

After creating the CSV, the script generates an HTML email summary. The email includes:

  • Total SharePoint site count
  • Total storage used
  • Total allocated storage
  • Over-utilized storage
  • Over-utilized percentage
  • Microsoft 365 Group-connected site count
  • Public Microsoft 365 Group count
  • Private Microsoft 365 Group count
  • Report date
  • Report generation timestamp

The CSV is attached to the email. If the email is sent successfully, the temporary CSV is deleted. If email delivery fails, the CSV is retained so that it can be reviewed manually.

CSV validation

The script creates a final object containing only the approved report columns. It then validates the CSV structure before and after exporting the file.

This validation helps prevent unwanted columns such as status, failed sites, Group ID, Microsoft 365 Group owners, Teams channel type, or modification date fields from appearing in the final report.

Troubleshooting

Certificate file not found

Check whether the certificate file exists: 

Test-Path "C:\Certificates\SharePointAutomationCert.pfx"

If the result is False, correct the $PfxPath value.

PnP PowerShell module not found

Check whether the module is installed: 

Get-Module PnP.PowerShell -ListAvailable

If required, install it: 

Install-Module PnP.PowerShell -Scope CurrentUser

Access denied

Possible causes include:

  • Admin consent was not granted.
  • The application has insufficient permissions.
  • The certificate does not match the certificate uploaded to Entra ID.
  • The wrong tenant or Client ID was entered.
  • The application cannot access the SharePoint site.

SMTP email failed

Check the following:

  • SMTP server name
  • Sender address
  • Recipient address
  • SMTP relay permissions
  • Firewall access
  • Required SMTP port
  • SMTP authentication requirements
  • Whether the sender is permitted to relay

Security recommendations

Never publish confidential tenant information.

Before uploading the script to GitHub or publishing it on a public website, remove or replace:

  • Real tenant names
  • Real tenant IDs
  • Real Client IDs, if your organization considers them confidential
  • Internal SMTP server names
  • Internal email addresses
  • Local certificate paths
  • Certificate passwords
  • Client secrets
  • Private certificate files such as PFX files

For production automation, store certificate passwords and other secrets in an approved secret-management solution such as Azure Key Vault, Azure Automation encrypted variables, or another enterprise-approved platform.
