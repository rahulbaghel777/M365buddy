What does this script do?

This script creates a consolidated SharePoint Online inventory containing site information, storage usage, site type, web creation date, site collection administrators, SharePoint owners and Microsoft 365 Group visibility. It connects to the SharePoint Admin Center, retrieves sites, processes each site and exports the final report to CSV.

Prerequisites

1. PowerShell 7 or later

PowerShell 7 or later is required because the script uses parallel processing.

$PSVersionTable

2. PnP PowerShell

Install-Module PnP.PowerShell -Scope CurrentUser
Get-Module PnP.PowerShell -ListAvailable
Import-Module PnP.PowerShell

3. Microsoft Entra ID application

You need an Entra application, client ID, tenant information, public certificate, private certificate, PFX password, required SharePoint/Graph permissions and admin consent.

Related setup article:
Register an Entra ID App for PnP PowerShell Certificate Authentication
This linked article will explain application registration, certificate creation, certificate upload, API permissions, admin consent, and authentication testing.

4. Certificate file

Update the PFX path in the script. The certificate must include the private key and match the certificate registered on the Entra application.

5. SMTP configuration — only if you want email

The standard version emails the CSV through the configured SMTP server. If you do not need email, you can remove the email portion and use the same script as a CSV-only report.

6. Output folder

The account running the script needs permission to write to the configured output folder.

Configuration values

Review the configuration section before execution and use placeholders when publishing the script publicly.

$Tenant = "contoso.onmicrosoft.com"
$ClientId = "YOUR-APPLICATION-CLIENT-ID"
$PfxPath = "C:\Certificates\SharePointAutomationCert.pfx"
$AdminCenterUrl = "https://contoso-admin.sharepoint.com"
$TenantRootUrl = "https://contoso.sharepoint.com"
$OutputDirectory = "C:\Reports\SharePointSiteInventory"
Security: Never publish PFX files, private keys, passwords, SMTP credentials or other secrets in a public GitHub repository.

Storage and over-utilization

Storage usage is converted from MB to GB using StorageUsageCurrent / 1024. Over-utilized storage is used storage minus allocated storage. The percentage is over-utilized storage divided by allocated storage, multiplied by 100. Negative over-utilization is treated as zero.

Email report behavior

The standard version creates the CSV first, builds an HTML email summary, attaches the CSV and sends it through Send-MailMessage. The temporary CSV is deleted only after successful email transmission. If email delivery fails, the CSV is retained.

Do not want email? Make it CSV-only

Yes — you can use the same script without email.
The CSV export happens before the email section, so you do not need to remove the inventory logic or the Export-Csv section.

1. Remove the email configuration

At the top of the script, remove or comment out:

$From = "SharePointReport@contoso.com"

$To = @(
    "admin@contoso.com"
)

$SmtpServer = "smtp.contoso.com"

2. Remove the complete email block

Find the section beginning with # EMAIL. Remove everything from that heading through the following try { ... } catch { ... } block containing Send-MailMessage.

Send-MailMessage `
    -From $From `
    -To $To `
    -Subject $Subject `
    -Body $Body `
    -BodyAsHtml `
    -Attachments $OutputCsv `
    -SmtpServer $SmtpServer `
    -ErrorAction Stop

Do not remove the CSV export section. Leave the earlier Export-Csv block intact. After this change the script generates the CSV and leaves it in $OutputDirectory; it does not contact SMTP and does not delete the CSV.

Troubleshooting

Certificate file not found

Test-Path "C:\Certificates\SharePointAutomationCert.pfx"

PnP PowerShell module not found

Get-Module PnP.PowerShell -ListAvailable
Install-Module PnP.PowerShell -Scope CurrentUser

Access denied

Check admin consent, application permissions, certificate matching, tenant/client ID and SharePoint access.

SMTP email failed

Check SMTP server, sender, recipients, relay permissions, firewall/port and authentication. If email is not required, remove the email block and use CSV-only mode.

Security recommendations

  • Never publish PFX files or private keys.
  • Never publish certificate passwords, client secrets or SMTP passwords.
  • Replace internal tenant names, IDs, SMTP servers, email addresses and local paths with placeholders.
  • Use approved secret management for unattended automation.
