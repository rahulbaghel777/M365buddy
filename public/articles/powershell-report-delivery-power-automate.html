Email PowerShell Reports Using Power Automate

Use a Power Automate flow to email a PowerShell-generated CSV without putting SMTP configuration in the script.

Production pattern: PowerShell generates and validates the SharePoint inventory CSV, uploads a uniquely named file to a SharePoint report folder, and Power Automate emails that file as an attachment. PowerShell does not send email in this version.

Overview

This guide uses the working SharePoint-to-Power-Automate pattern: PowerShell → SharePoint file → Power Automate → Outlook email. It is designed for the SharePoint Online site inventory script and keeps the inventory collection and CSV validation logic separate from email delivery.

The production script creates a local CSV first, validates its columns, and then uploads it to the destination SharePoint library. The local copy is retained for troubleshooting. The uploaded filename includes a date and time so each successful run creates a new file and can trigger the flow.

Before you begin

  • PowerShell 7 and a compatible, installed PnP.PowerShell module.
  • An Entra application and certificate configured for the SharePoint inventory operations in your tenant.
  • The application must have the permissions needed to read the inventory and write a file to the destination report site. If you use Sites.Selected, verify that the app has an appropriate permission grant on the target site.
  • An existing SharePoint site, document library, and destination folder. The folder must be accessible by the app and the Power Automate SharePoint connection.
  • A Power Automate SharePoint connection and a Microsoft 365 Outlook connection.
  • A tenant DLP policy that permits the SharePoint and Outlook connectors to be used together. In your policy, both connectors must be in the same approved data group; use the Business group if that is your organization's approved configuration.
Credential security: The public script uses a secure password prompt; it does not contain your PFX password. Never commit a populated local script, a PFX file, or a real password to a public repository. For unattended scheduled execution, configure an approved secret-management approach and test it under the account that runs the task.

Configure the PowerShell script

Download the script and edit the configuration section near the top. Keep the script's existing CSV columns and calculations unchanged unless you intend to change the report itself.

SettingWhat to configure
$TenantYour tenant domain, such as contoso.onmicrosoft.com.
$ClientIdThe client ID of your Entra application.
$PfxPathThe full local path to the PFX certificate file. Do not upload the PFX to the website or report library.
$AdminCenterUrlYour SharePoint admin-center URL.
$SharePointRootUrlYour tenant's SharePoint root URL.
$OutputDirectoryA local directory where the generated CSV can be created and validated.
$ReportSiteUrlThe site containing the SharePoint document library that the flow monitors.
$ReportFolderThe site-relative library/folder path where the CSV should be uploaded. Create this folder first.

Example destination settings—replace these examples with your actual site and folder:

$ReportSiteUrl = "https://contoso.sharepoint.com/sites/SharePointReports"
$ReportFolder  = "Shared Documents/Reports/SharePointSiteInventory/Incoming"

Important: use the same site and destination folder in both the PowerShell configuration and the Power Automate trigger. The script prompts for the PFX password when it runs. Do not paste the password into the public copy of the script.

Run the report and upload it

  1. Confirm that the destination folder exists and that the application can upload a file there.
  2. Open PowerShell 7 and run the downloaded script from its local location.
  3. Enter the PFX password when prompted.
  4. Wait for the inventory run, CSV validation, and SharePoint upload to finish.
  5. Open the destination folder and confirm a new SharePointSiteInventory_*.csv file is present.
& "C:\Scripts\SharePoint\SharePoint_Site_Inventory_PowerAutomate.ps1"

Replace the example local path in the command with the location where you saved the script. The script retains its local CSV copy. Do not run it repeatedly while the first inventory run is still in progress.

Create the automated cloud flow

1. Create the flow

In Power Automate, select Create → Automated cloud flow. Give it a name such as SharePoint Site Inventory Email. Add the SharePoint trigger When a file is created (properties only).

2. Configure the trigger

  • Site Address: the same SharePoint site configured in $ReportSiteUrl.
  • Library Name: choose the document library that contains the configured report folder. The display name may be Documents even when its URL includes Shared Documents.
  • Folder: use the folder picker to select the Incoming folder configured in $ReportFolder.

The flow must monitor the folder where the script uploads the report, not the local output directory or the site root.

3. Add a condition to ignore unrelated files

Add a Condition after the trigger:

FieldValue
Left valueFile name with extension from the trigger
Operatorstarts with
Right valueSharePointSiteInventory_

Add the remaining actions inside the If yes branch. Leave If no empty for this initial production version.

4. Get the file content using path

Add SharePoint → Get file content using path. This is the action used in the successful test. Using Get file content with an unsuitable identifier produced a 404 “File not found” error, so keep the path-based action.

  • Site Address: the same report site used by the trigger.
  • File Path: select the trigger's Full Path dynamic content. Do not type an encoded identifier or use only the file name.
File not found? Check that the trigger and content action use the same site, and verify that File Path is the trigger's Full Path token. Do not substitute File name with extension.

5. Send the email attachment

Add Microsoft 365 Outlook → Send an email (V2) after the content action.

FieldValue
ToYour approved recipient or distribution group
SubjectSharePoint Site Inventory Report
BodyExplain that the SharePoint site inventory CSV is attached.
Attachment NameFile name with extension from the trigger
Attachment ContentFile Content from Get file content using path

Resolve Flow checker DLP errors

If Flow checker says the shared_sharepointonline connector cannot be combined with shared_office365 because of DemoPolicy, this is a data-loss-prevention policy issue, not a PowerShell or CSV issue.

  1. Open the Power Platform admin center and edit the applicable data policy, if you have the required admin permissions.
  2. Review the connector groups for SharePoint and Office 365 Outlook.
  3. Ask the Power Platform administrator to place both connectors in the same approved data group, commonly Business for this organizational reporting use case, subject to company policy.
  4. Save the policy, allow it to propagate, reopen the flow, and run Flow checker again.

Do not delete or disable the DLP policy just to make the flow pass. If you do not administer the policy, ask your Power Platform administrator to make the approved change.

Test the complete workflow

  1. Save the flow and ensure it is turned on.
  2. Run the PowerShell script again so it creates a new timestamped report after the flow is enabled.
  3. Check the SharePoint folder and confirm the new file was uploaded.
  4. Open the flow's run history. Confirm the trigger, condition, Get file content using path, and Send an email (V2) all succeed.
  5. Open the received message and verify that the attached CSV is readable and contains the expected columns.

A file created before the flow was enabled will not normally trigger a new run retroactively. Generate a new file for each test.

Production operations and retention

  • Keep report-library access restricted to the people and automation accounts that need it; inventory exports may reveal internal site names and URLs.
  • Each script run produces a timestamped filename, preventing routine runs from overwriting the same file and allowing the creation trigger to fire.
  • The local CSV remains on the computer that runs PowerShell. Apply an approved local retention and cleanup policy.
  • The uploaded SharePoint report remains in the destination folder after email delivery. Decide on an approved retention or archive policy before adding any move/delete action.
  • For unattended Task Scheduler use, replace interactive password prompting with your approved secret store or protected certificate-storage design and test using the scheduled-task identity before production scheduling.
  • Monitor Power Automate run history and configure failure notifications according to your team's operational requirements.

Troubleshooting

Flow checker reports a DLP violation

Have the policy owner review the data groups for SharePoint and Office 365 Outlook. Keep them in a policy-approved compatible group.

The flow does not trigger

Confirm the flow is on, the trigger watches the exact destination site/library/folder, and the script uploaded a newly created timestamped file after the flow was enabled.

Get file content returns 404

Use Get file content using path with Full Path from the trigger. Verify the site address matches the trigger and the target file still exists at that path.

The email arrives without a working attachment

Set Attachment Name to File name with extension from the trigger and Attachment Content to the file-content output from Get file content using path, not to the trigger body or an identifier.

The PowerShell upload fails

Check that the site URL and site-relative folder path are correct, the destination folder exists, the certificate is valid, and the Entra app has write access to the target site. The script deliberately retains the local CSV when upload fails so you can retry after fixing the problem.
